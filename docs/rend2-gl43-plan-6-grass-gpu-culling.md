# План 6. GPU-отсечение и LOD спрайтов травы (compute + indirect)

Относится к [rend2-gl43-review.md](rend2-gl43-review.md), строка «Foliage: auto grass, wind, flutter». Объём:
средний–большой (1–2 недели). **Шаг 0 решает, делать ли дальше.** Отправная точка — внешнее ревью, где
«GPU foliage culling» назван хорошим кандидатом; в первом обзоре это было упущено.

## Что сейчас

**Генерация** (`R_GenerateSurfaceSprites`, `shared/rd-rend2/tr_bsp.cpp`, около строки 4162): при загрузке карты
на каждую BSP-поверхность со стадией surfaceSprites. Спрайты всех поверхностей лежат в одном VBO, структура
`sprite_t`: position(+w), normal, color, widthHeight + skew. **Каждый спрайт записан 4 раза** (по разу на угол
квада), индексы — 6 на спрайт. У поверхности есть `spriteMins/Maxs`: границы якорей, расширенные на размер
карточки.

**Отрисовка** (`RB_SurfaceSprites`, `shared/rd-rend2/tr_surface.cpp`, около строки 2671):
- одна поверхность — один DrawItem (или несколько кусков по лимиту индексов), без отсечения отдельных спрайтов;
- **карточки** (`r_grassCardMode`): инстансы 2 или 3, выбираются по расстоянию до границ **всей поверхности**;
- **полоски** (`r_grassBendSegments`): если любая часть поверхности ближе `r_grassBendLodDist`, **вся**
  поверхность рисуется изогнутыми полосками. Это `2 · (segments + 1)` вершин (10 при 4 сегментах) на карточку, а
  спрайт идёт инстансом (`stepRate = numInstances`, чтение каждого 4-го `sprite_t`);
- **дальний fade** — в вершинном шейдере (`glsl/surface_sprites.glsl`, `main`): `fadeScale ≥ 1` даёт вырожденную
  вершину `gl_Position = vec4(0.0)`. Но шейдер для неё **всё равно запускается** для каждой вершины каждого спрайта.

Одна и та же геометрия рисуется в prepass, velocity, каждом каскаде CSM и цветовом проходе (комментарий в
`RB_SurfaceSprites`: «prepass, velocity, cascade and colour passes draw the same geometry»). Вершинная часть
тяжёлая: ветер `FoliageWind`, поле изгиба `FoliageFieldDisplacement`, нерастяжимый изгиб `FoliageBladeBend`.

**Что теряется:**
1. Спрайты поверхности вне пирамиды вида обрабатываются полностью. Большая поверхность земли наполовину за
   камерой — половина работы впустую, и так в каждом проходе. Каскады CSM ортогональные и узкие, там доля лишнего
   ещё больше.
2. Спрайты за дистанцией fade прогоняют вершинный шейдер ради вырожденной вершины.
3. LOD по поверхности: одна близкая точка переводит всю поверхность в полоски с 3 карточками, даже её дальний край.

## Зачем GL 4.3

Отбор по каждому спрайту на CPU — сотни тысяч проверок на вид и загрузка списков каждый кадр. Compute делает отбор
на GPU, сжимает видимых в список (атомики, SSBO) и сам задаёт число инстансов через indirect draw. CPU не узнаёт
число видимых и ничего не ждёт.

## Как сделать

### 1. Данные спрайтов для GPU (загрузка)

- В `R_GenerateSurfaceSprites` (или после сборки общего VBO спрайтов) собрать **один компактный буфер записей**:
  один спрайт — 64 байта (4 × RGBA32F): `position.xyzw`, `normal.xyz + pad`, `color.xyz + pad`,
  `widthHeight.xy + skew.xy`. Это четверть от нынешних 4 копий, и выравнивание кратно 16 байтам.
- Буфер доступен ядру как SSBO, вершинному шейдеру — как **buffer texture** (`samplerBuffer`, RGBA32F, 4
  `texelFetch` на спрайт). Не SSBO: в ядре GL 4.3 минимум хранилищ в вершинном шейдере равен 0
  (`GL_MAX_VERTEX_SHADER_STORAGE_BLOCKS`), а TBO работает везде.
- У `srfSprites_t` добавить `firstSprite` (индекс в компактном буфере) и радиус ограничивающей сферы спрайта.
  Радиус: максимум `width · (1 + u_FadeScale) · r_grassCardWidth`, высоты, `|skew|` и изгиба. Изгиб ограничен в
  `FoliageBladeBend` половиной высоты (`maxLen = 0.5 · h`), смещение ветра — его амплитудой. Радиус считать в
  ядре из uniforms, чтобы cvar ветра работали без перезагрузки.

### 2. Ядро отбора `glsl/sprite_cull.glsl`

**Задания.** В бэкенде каждый `RB_SurfaceSprites` в GPU-режиме не рисует сразу, а добавляет **задание** в список
прохода: `firstSprite, numSprites, outputBase, fadeStart, fadeEnd, параметры LOD, индекс indirect-команды`.

**Диспатч.** Один на проход, по потоку на спрайт всех заданий. Задание по номеру потока находится по префиксной
таблице заданий (двоичный поиск в shared memory) или одной рабочей группой на 64 спрайта одного задания.

**Каждый поток:**
1. Сфера `position + радиус` против плоскостей пирамиды **этого** вида: 4 боковые плюс far, для каскада —
   ортогональные плоскости.
2. Fade: расстояние до `u_SpriteViewOrigin`, а не до камеры прохода. Для каскадов это главная камера, поэтому тени
   совпадают с травой. Если `fadeScale ≥ 1` — спрайт отбрасывается.
3. LOD: близкий спрайт — в список «полоски, 3 карточки», дальний — в «квады, 2 или 3 карточки», по тем же порогам
   `r_grassBendLodDist`, `r_grassCardLodDist`, но **на спрайт**.
4. `atomicAdd` в счётчик своего списка, запись индекса спрайта.

**Итог.** Ядро пишет `instanceCount` в `DrawArraysIndirectCommand` двух команд задания:
- полоски: `count = 2 · (segments + 1)`;
- квады: `count = 4`, `GL_TRIANGLE_STRIP`.

Порядок в списке недетерминирован. Это допустимо: в GPU-режим идут только не-blended спрайты, то же условие, что
для карточек в `RB_SurfaceSprites` (blended без alpha test остаются на старом пути).

**Барьер** перед отрисовкой прохода: `GL_COMMAND_BARRIER_BIT | GL_VERTEX_ATTRIB_ARRAY_BARRIER_BIT |
GL_TEXTURE_FETCH_BARRIER_BIT`.

### 3. Отрисовка

- Новый тип `DRAW_COMMAND_ARRAYS_INDIRECT` в `DrawItem` и `switch` `RB_DrawItems` (`tr_backend.cpp`, около строки
  1180): привязка `GL_DRAW_INDIRECT_BUFFER` и `glDrawArraysIndirect`. Загрузить `qglDrawArraysIndirect` (ядро GL
  4.0) в `GLimp_InitModernFunctions` (`tr_extensions.cpp`) и `qgl.h`.
- Список видимых индексов — **инстансный атрибут** `uint` (`stepRate = numCards`), смещение атрибута = начало
  списка задания (offset в `vertexAttribute_t`). `baseInstance` и `ARB_shader_draw_parameters` не нужны.
- Вершинный шейдер: новый define `USE_SPRITE_LIST`. `attr_Position`, `attr_Normal`, `attr_Color`,
  `attr_Position2` берутся из TBO по индексу из атрибута, номер карточки — `gl_InstanceID % numCards`. Логика
  вершины готова: это нынешняя ветка полосок `SpriteVertex` (`u_GrassStrip.x > 0`), квад — полоска из одного
  сегмента. Проверить на `FACE_UP`: порядок вершин полоски даёт углы 0, 3, 1, 2 — тот же квад.
- Проверка fade в шейдере остаётся (её частично прошедшие спрайты по-прежнему сужаются), но полностью исчезнувшие
  до шейдера уже не доходят.

### 4. Где запускать ядро

- DrawItem складываются в проход и рисуются в `RB_SubmitRenderPass` (`tr_backend.cpp`, около строки 1550). В
  начале этой функции, если у прохода есть задания спрайтов, — диспатч, затем обычный `RB_DrawItems`.
- **Повторное использование.** Prepass, velocity и цветовой проход одного вида должны рисовать **одинаковое**
  множество спрайтов: prepass пишет глубину, цвет может рисоваться с `GL_EQUAL`. Поэтому результат кэшировать на
  кадр по паре (`viewParm`, поверхность): отбор детерминирован по входам вида, но второй прогон атомиков дал бы
  другой порядок и повторную работу. Первый проход вида считает, остальные берут готовые команды.
- Буферы выхода — кольцо `MAX_FRAMES`, ёмкость в индексах = сумма спрайтов поверхностей вида. Переполнение →
  остаток заданий идёт по старому пути с предупреждением один раз.

### 5. Переключатели

- `r_surfaceSpritesCompute`, без рестарта:
  - **0** — нынешний путь;
  - **1** — только отсечение: LOD по поверхности как сейчас. Картинка должна совпасть с режимом 0: те же
    треугольники, отброшены только невидимые и полностью исчезнувшие;
  - **2** — отсечение и LOD на спрайт. Картинка вдали немного меняется: квады вместо полосок, но квады лежат на
    хорде полоски.
- По умолчанию 0 до проверки. Нет GL 4.3 или кончилась ёмкость — старый путь.

### 6. Потом (опционально)

Отсечение перекрытых спрайтов по Hi-Z прошлого кадра (`tr.screenHiZImage`, есть при SSR/SSGI) с репроекцией.
Отдельный шаг, только если после пунктов 1–5 трава останется дорогой.

- **SDL-тест** в `tools/rend2/test_gl43_compute.py`: случайные спрайты и пирамида вида. Видимые = брутфорс на
  Python с тем же радиусом; ни один спрайт, хоть одна вершина которого попадает в пирамиду (выборка вершин

  - Скриншоты `r_surfaceSpritesCompute 0` и `1` в одинаковой позиции при `r_foliageWindDebug 3` (замороженный
    ветер): разница ровно 0.
  - Режим 2 — визуально, на дальних краях полей.
  - Тени травы в каскадах.
  - Взаимодействие с персонажем (`r_foliageInteraction`).
  - Замеры шага 0 до и после.

## Риски

- Недооценка радиуса — трава исчезает на краю экрана при сильном ветре или изгибе. Лечится запасом и тестом с
  максимальными cvar.
- Velocity-проход использует прошлые позиции (ветер прошлого кадра): радиус должен покрывать и их.
- Fog-проход спрайтов (`SSDEF_FOG_MODULATE`) и FX-спрайты (`SSDEF_FX_SPRITE`): либо тот же список, либо старый
  путь — решить на первом шаге.

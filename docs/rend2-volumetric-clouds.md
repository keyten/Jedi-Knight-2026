# Rend2: volumetric clouds (`r_clouds`) and cloud shadows (`r_cloudShadows`)

A cloud renderer of its own, next to the froxel fog ([rend2-volumetric-fog.md](rend2-volumetric-fog.md)) and the
atmosphere ([rend2-atmosphere.md](rend2-atmosphere.md)). The froxel grid ends a few thousand units from the camera;
clouds are kilometres away and above, so they get their own representation: a spherical shell between two altitudes,
ray marched only inside that shell, only on sky pixels, at reduced resolution, with a temporal history of their own.
The froxel grid is **not** extended.

Default off (`r_clouds 0`, latched). No assets: all noise is generated by the renderer.

Files: `shared/rd-rend2/tr_clouds.cpp`, `glsl/clouds_common.glsl` (library), `clouds_noise.glsl`, `clouds_march.glsl`,
`clouds_resolve.glsl`, `clouds_composite.glsl`, `clouds_shadow.glsl`; the cloud shadow lookup in `lightall.glsl` and
`volumetric_inject.glsl` (`USE_CLOUD_SHADOWS`); GPU checks and timings in `tools/rend2/test_clouds_gl.py`.

## Architecture

| pass | when | resolution | output |
|---|---|---|---|
| noise generation | first frame with clouds (once per renderer start) | 128³ + 32³ + 512² | `*cloudShape` R8, `*cloudDetail` R8, `*cloudWeather` RG8 (3D, 1 layer) |
| cloud shadow map (`r_cloudShadows`) | `RB_DrawSurfs` of the main view, before the depth passes, froxel injection and surfaces | 512² | `*cloudShadow` R16F |
| march | `RB_SubmitRenderPass`, after the atmosphere composite | 1 / `r_cloudScale` per axis | `*cloudMarch` RGBA16F (S, T) + R16F cloud distance |
| temporal resolve | right after the march | same | `*cloudHistory0/1` ping-pong |
| composite | right after the resolve, before the froxel composite | full | renderFbo colour + glow (`atmosphereCompositeFbo`) |
| sun ray mask | `RB_RenderMainPass`, after the sun flare | full | `tr.sunRaysFbo` × T |

Only the main world view of the first scene of a frame gets clouds (as the atmosphere): portals, mirrors, the sky
portal view, cubemap captures and shadow views keep their look. On sky portal maps the "sky" is the portal scene, so
clouds are off there unless `r_cloudSkyPortal 1` (then composited over everything at depth 1, an approximation).

## Geometry and units

Cloud space is in kilometres: x / y are the world axes, z is the height above the ground. The ground and the scale are
the atmosphere's: `r_atmosphereGroundZ` (auto = the lowest floor of the map) and `r_atmosphereUnitScale` (0.03 m per
unit), used even with the atmosphere off. The planet centre is fixed at (0, 0, −6360 km), never camera centred, so the
layer does not move with the camera and the history stays valid. The shell bends down to the horizon; the march stops
at `r_cloudMaxDistance` (60 km) and fades out over its last 30 %.

`CloudInterval` handles cameras below, inside and above the layer (one interval, the nearest), and the ground hides
everything behind it. Altitudes are formed without r² − R² cancellation. The rays come from a camera relative inverse
view-projection (no translation): with the full inverse a camera 80 000 units from the origin lost ~1e-4 rad to float
precision (tens of metres at a cloud 20 km away, found by the test harness); now the intersections match a float64
reference to well under 2 m plus the conditioning of the ray.

## Density and noise

```
coverage   = saturate(weather.r + 2 r_cloudCoverage − 1) × legacy mask      0 clear, 0.5 = the map, 1 overcast
profile    = height profile by cloud type (weather.g: 0 flat stratus, 1 tall cumulus)
cloud      = saturate(remap(shape × profile, 1 − coverage, 1, 0, 1)) × coverage
erosion    = detail noise, wispy at the base, billowy at the top (r_cloudDetail, 0 = off)
extinction = cloud × 60 /km × r_cloudDensity
```

Exactly 0 where there is no cloud, so a clear sky (or `r_cloudCoverage 0`) leaves the frame bit exact.

**Noise**: renderer generated, deterministic, tiling in x, y and z (every period divides the texture):

| texture | content | size, memory |
|---|---|---|
| shape | billowy Perlin fbm dilated by a Worley fbm, eroded by a finer Worley fbm (Schneider 2015 / Hillaire 2016), one channel | 128³ R8 + mips, 2.4 MB |
| detail | Worley fbm | 32³ R8 + mips, 37 KB |
| weather | r = coverage (Perlin fbm + cells), g = cloud type (very low frequency Perlin) | 512² RG8 + mips, 0.7 MB |

`clouds_noise.glsl` draws every slice into a float scratch texture (integer hash `pcg3d` of the wrapped cell), the
CPU reads it back and **histogram equalizes** it into bytes (rank in 4096 bins, linear inside a bin), then uploads it
with mips. The raw shape values bunch around their mean (0.63 – 0.97, σ 0.04): quantized directly to 8 bits they would
use a few dozen levels; equalized, all 256 levels are used evenly and a coverage c leaves exactly a fraction c of the
field above the threshold (checked: 0.250 / 0.500 / 0.750). Two generator runs are bit identical (Intel and NVIDIA
each; values may differ between vendors by float rounding). The octave counts are fixed in the generator; the per
sample cost is set by cvars only (steps, light steps, detail on / off).

Wind (`r_cloudWindSpeed` m/s, `r_cloudWindDir` degrees) scrolls the shape and weather maps; the detail drifts 1.3×
faster and rises 0.3 m/s so the edges boil. Offsets are wrapped per tile in double precision on the CPU (no precision
loss in long sessions), time is `refdef.time`.

## Lighting

Per sample with extinction σ, exact per step integration (energy conserving, Hillaire):

```
L = E_sun(h) · π · Σ_i b^i · p(μ, c^i g) · exp(−a^i τ_sun) + ambient(h)        a = b = c = 0.5, i < r_cloudMSOctaves
S += T · L · (1 − exp(−σ dt)),  T *= exp(−σ dt)
```

- **Sun**: with the atmosphere composited in this view, the top of atmosphere sun × `AtmoTransmittanceToSpace` at the
  sample's altitude (the clouds redden at sunset with it); otherwise the map sun (`R_AtmosphereSunGround`, the same
  colour the atmosphere uses), faded as it sets.
- **Phase**: dual lobe Henyey-Greenstein, 0.8 × HG(`r_cloudAnisotropy`, 0.6) + 0.2 × HG(−0.3).
- **Self shadow**: τ_sun from `r_cloudShadowSteps` (5) taps towards the sun, quadratically spaced over the layer
  thickness (0.3 – 3 km), the first two with erosion, plus one long tap beyond. The taps reuse the sample's weather
  coverage / type (their few km are nothing against the 40 km weather tile).
- **Multiple scattering**: Wrenninge 2013 octaves (extinction, scattering and g halved per octave). This is a cloud
  approximation of its own; the froxel fog's multiple scattering coefficient is not used.
- **Ambient** (isotropic, conservative): with the atmosphere, the mean of its sky-view LUT over the upper hemisphere
  (zenith + a ring at 25°) plus a ground bounce (albedo 0.3, the sun at the ground); without it, 0.15 × the sun's
  luminance, bluish, plus the same bounce. Darker at the base (0.5× at the base to 1× at the top), `r_cloudAmbient`.
  The atmosphere builds its sky-view LUT when clouds are on (`RB_CloudsWantSkyView`), even in its overlay sky mode.
- No dynamic lights (sabers and dlights do not reach clouds kilometres up).

## Temporal

- Own history (not the froxel or SMAA history): RGBA16F (S, T) + R16F transmittance weighted cloud distance,
  ping-pong.
- The march start is jittered per pixel and frame (interleaved gradient noise, 64 frame cycle).
- Resolve: the cloud point (camera + direction × cloud distance) is moved back by the wind × frame time and
  reprojected with the previous frame's view-projection (without the SMAA T2x jitter, which would only shake the
  history). The history is fetched bilinearly over pixels that saw sky, clamped to this frame's 3×3 neighbourhood
  widened by 0.5 of its size (a tight box kept most of the jitter noise: 1.7× vs 2.3× noise reduction in the test), and
  blended with `r_cloudTemporal` (0.9).
- Reset: camera cut (`tr.temporalHistoryValid`), teleport > 4096 units, > 250 ms between frames, map change, viewport
  change, any change of the parameters that shape the clouds (history key), debug views.

## Composition order

```
sky (SS_ENVIRONMENT) ... opaque / decals up to SS_FOG
→ atmosphere composite (aerial perspective, analytic sky)
→ early sun (RB_DrawSun, only with clouds on)
→ cloud composite (sky pixels)
→ froxel composite (local fog in front of everything, clouds included)
→ blended layers > SS_FOG (glass, water) → sun rays (× cloud T) → post process
```

With the aerial perspective S_ap, T_ap to the cloud distance Dc, the sky behind the cloud seen from the cloud is
(dst − S_ap) / T_ap, so `out = T_ap S_c + (1 − T_c) S_ap + T_c dst`: one draw, blend ONE, SRC_ALPHA, colour
`(T_ap S_c + (1 − T_c) S_ap, T_c)`, glow × T_c, destination alpha kept. The aerial perspective uses the physical
distance (the atmosphere's `r_atmosphereAerialScale` exaggerates short JA views only). Without the atmosphere,
`out = S_c + T_c dst`.

- **Opaque geometry**: clouds only where the full resolution depth is 1. The march marks low resolution pixels without
  any sky; the upsample uses only neighbours that saw sky (no halos on silhouettes); geometry pixels are untouched.
  Indoors through a window: the window's sky pixels get clouds, the room does not.
- **Local fog**: the froxel composite runs after the clouds and treats sky pixels at the sky distance plus its
  analytic tail, so fog between the camera and the clouds attenuates them with its own T.
- **Sun**: `RB_DrawSun` normally draws after every composite. With clouds on it is drawn after the atmosphere composite
  (whose analytic sky replaces sky pixels) and before the clouds, so clouds cover the sun and froxel fog now dims it
  (an intended change, only with clouds on). The sun quad keeps depth 1. The sun flare target used by the sun rays is
  multiplied by the clouds' T.

## Cloud shadows (`r_cloudShadows`, default 0)

A 512² R16F map of the clouds' sun transmittance for points of the ground plane in a camera centred square of
`r_cloudShadowExtent` km (8: larger than any JA map at 0.03 m/unit), its centre snapped to texels, rebuilt every
`r_cloudShadowInterval` frames before the froxel injection and the surfaces. Everything it lights is below the cloud
base, where the transmittance is constant along the sun, so a world point slides along the sun onto the plane:
`q = p.xy − sun.xy / sun.z · (p.z − ground)`. Faded at the map edge and for a sun below ~6°.

One factor for both consumers:
- **surfaces**: lightall multiplies the sun visibility (the cascaded shadow) by it, so it acts wherever the sun shadow
  does (`r_sunlightMode 1` lightmap modulation, 2 direct sun);
- **froxel fog**: the sun injection (raster and compute) multiplies the sun by it; the froxel history key includes
  the cloud shadow switch.

Compiled in only with `r_clouds` (`USE_CLOUD_SHADOWS` in the shader header; unit `TB_CLOUDSHADOW` 31, needs 32
fragment / compute texture units, else off with a warning). With `r_clouds 0` lightall and the injection are the same
code as before.

## Legacy `fx_cloudlayer` (SP)

What the entity really carries (`code/game/g_fx.cpp` `SP_fx_cloudlayer`, `code/cgame/cg_ents.cpp` `CG_Clouds`,
`RB_SurfaceClouds`): its origin (networked), `radius` (outer radius, 2048), `random` (inner radius of a TUBE layer, 128),
`wait` (curvature towards the edge), spawnflags 1 TUBE, 2 ALT (`gfx/world/haze2`). The game reads the keys from game
memory, cgame draws one `RT_CLOUDS` entity: a lathed flat disc / ring (12 segments) with a baked alpha profile and a
scrolling haze texture. No density, randomness, height or wind: `random` is a radius, not noise. At 0.03 m/unit the
origin height and radius are tens of metres, not cloud altitudes. MP has no `fx_cloudlayer`, `ET_CLOUD` or
`CG_Clouds` (only the `RT_CLOUDS` enum). None of the 63 stock BSPs (assets0–3, ZZ_SPMissExpansV1) has one.

Bridge (renderer only, no cgame / game change): with `r_clouds 1` and `r_cloudLegacy` ≥ 1, `R_AddEntitySurface`
hands the `RT_CLOUDS` entity of the main view to `R_CloudsCaptureLegacy`, which records it and skips its haze disc;
mirrors / portals keep the legacy surface. With `r_clouds 0` (or the clouds off on that map) nothing changes.
- `r_cloudLegacy 1` (hint): the entity only picks a style. TUBE leaves the sky above the camera open (coverage ramps
  up from 1 to 6 km around the camera); ALT is a thin haze (0.45× density, 1.5× erosion, flat cloud type). Altitudes
  stay on the cvars. `wait` (curvature) is ignored: the shell already curves, its meaning does not carry over.
- `r_cloudLegacy 2` (literal, debug): the entity's height above the ground is the cloud base (the cvar thickness is
  kept) and the clouds are confined to its disc / ring (`radius`, `random`).
- `r_cloudLegacy 0`: ignored, the legacy haze is drawn.

Validation without a stock map: `r_cloudLayerTest <x> <y> <z> <radius> [inner] [flags]` injects a fake layer
(`clear` removes it); `r_cloudDebug 9` shows the mask; `r_cloudInfo` prints the captured or test layer.

## GPU cost and memory

Measured with `python tools/rend2/test_clouds_gl.py --bench` (the real shaders, default cvars, real noise, engine
formats, 1920×1080, every pixel sky = worst case; GL_TIME_ELAPSED). Not measured in game yet.

| | RTX 2060 (616.92) | Intel UHD (27.20.100.8280) |
|---|---|---|
| march 960×540, towards the horizon, coverage 0.5 / 0.9 | 2.01 / 1.47 ms | 33.0 / 18.8 ms |
| march 960×540, looking up, coverage 0.5 | 1.33 ms | 41.2 ms |
| march 480×270 (`r_cloudScale 4`), horizon / up | 0.76 / 0.53 ms | 7.6 / 9.4 ms |
| resolve 960×540 / 480×270 | 0.15 / 0.04 ms | 3.4 / 0.7 ms |
| composite 1920×1080 | 0.19 ms | 2.7 – 3.3 ms |
| cloud shadow map 512², 10 steps | 0.16 ms | 3.2 ms |
| noise generation (once) | 35 ms GPU + read back / equalize | 360 ms GPU + read back / equalize |

The noise is generated on the first frame with clouds: a one time hitch (~0.4 s on the iGPU). On integrated GPUs use
`r_cloudScale 4`, fewer steps (`r_cloudSteps 32`) and `r_cloudDetail 0`.

Memory at 1920×1080: march + 2 history (RGBA16F + R16F) 15.6 MB at scale 2 (3.9 MB at 4, 62 MB at 1), noise 3.1 MB,
shadow map 0.5 MB; ≈ 19 MB at the default scale (`r_cloudInfo` prints it). 0 with `r_clouds 0`.

## Limitations

- Clouds only on sky pixels (depth 1): a layer placed below the map's skybox geometry is hidden by it.
- Lens flares (`RB_RenderFlares`) are not occluded by clouds; the sun flare query still counts unoccluded samples.
- Sky portal maps: off by default, `r_cloudSkyPortal 1` is approximate.
- Blended surfaces sorted ≤ SS_FOG that do not write depth get clouds composited over them where they cover sky (the
  atmosphere has the same limit); layers above SS_FOG are fine.
- Disoccluded pixels (silhouettes moving over the sky) are noisy for a few frames; fast cloud motion against the
  widened clamp can ghost slightly.
- One interval per ray: a camera above the layer looking down at a grazing angle misses the far part of the shell.
- Cubemap captures, mirrors and portals have no clouds (static captures of moving clouds would be wrong anyway).
- Cloud shadows act through the sun shadow term: baked lightmap sun is only darkened with `r_sunlightMode 1`
  modulation, as for the cascades. The cloud shadow map ignores the planet curvature (negligible over 8 km).
- Generated noise can differ between GPU vendors by float rounding (each vendor is deterministic).
- Fixed: one cloud layer; no cirrus layer, no lightning, no rain shafts coupled to the weather system.

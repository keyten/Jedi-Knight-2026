# Render-only water geometry

`r_waterGeometry 1` (latched, default 0) builds a second static mesh at BSP load. It leaves BSP faces, collision and gameplay unchanged. It requires `r_waterSurface 1`; `r_waterWaves 1` enables its displacement. OpenGL 3.2 uses CPU subdivision at map load and a vertex shader at draw time. The CPU does no per-frame mesh work.

## Stock geometry and draw path

The installed stock audit (`rend2-water-body-stock-audit.json`) records modern-water `MST_PLANAR` faces (BSP type 1) and `MST_PATCH` grids (type 2). `t2_rancor` has six separate 4096-unit-area planar pools. `t3_hevil` has nine modern planar surfaces, including a 7-surface lake body; its eight vertical patch waterfalls remain legacy. `yavin1` has four modern planar surfaces and eleven modern patches; its larger bodies span 9 and 17 surfaces. `vjun1` has one large planar slime surface. This path consumes each surface's already-triangulated indices, so neither convexity nor quad topology is assumed. `SF_TRIANGLES` is supported for overrides and future maps.

Classification and body grouping happen after BSP surfaces load. `R_CreateWorldVBOs` packs positions, normals and primary UVs for ordinary world drawing. The geometry builder runs after environment profile overrides and world VBO creation, before leaf merging. It creates one extra VBO/IBO per eligible body and per-surface index ranges. Only the modern-water draw selects these buffers. The first textured stage's `tcMod` continues to act on the original interpolated primary UVs. Portal and sky surfaces never receive a water mesh. Eligible water surfaces are excluded from leaf merging while this option is on, preserving their ranges and body IDs.

The existing SP cached BSP handoff and optional `.tspace` sidecar supply source map data and tangent space. Neither caches GPU water geometry. This mesh is derived from the current classified surfaces and body overrides on every map load, so it cannot become stale when water CVARs or `env.json` profiles change.

## Tessellation, seams, and boundaries

The longest original triangle edge in a body sets a common dyadic subdivision level. An edge midpoint cache shares vertices between triangles of the same BSP surface. Matching edge segments on touching surfaces therefore get identical positions and wave phases. With `r_waterShoreline 0`, different original BSP surfaces with unmatched edge partitioning retain the compatible downward 64-unit render skirts. With `r_waterShoreline 1`, map-load boundary classification replaces that blanket treatment with attenuated rigid-wall overlap skirts and short outward natural-bank wedges; see `rend2-water-shoreline.md`.

The builder records the largest final top-surface edge after subdivision. At draw time a candidate macro component enters geometry only when its wavelength is at least four times that measured edge. Quality still caps the candidate set at one or two longest terms, but budget-reduced or intrinsically coarse bodies can resolve fewer (including zero). Rejected terms remain in fragment shading and therefore never alias into false low-frequency silhouette motion. The resolved vertex slope is interpolated to the fragment; only the complementary analytic terms are evaluated per pixel. The original world position is retained as `basePosition`; the displaced world position drives projection, depth writing, refraction, view vectors, SSR, and Snell tests. The body plane remains available for grouping and planar reflection capture. Bounds expand conservatively for vertical motion, horizontal drift, the full interactive-height clamp and skirts; the flat face plane is no longer used to cull these meshes.

## Budgets and diagnostics

- `r_waterGeometryEdge 64`: target maximum triangle edge length, clamped to 16–512 world units.
- `r_waterGeometryBodyVerts 250000`: per-body vertex cap.
- `r_waterGeometryMapVerts 1000000`: whole-map vertex cap.
- `r_waterGeometryDebug`: 1 wireframe, 2 displacement magnitude, 3 original triangulation with the same wave, 4 body colors with skirts in red, 5 expanded surface culling bounds.
- `r_waterGeometryInfo`: per-body vertices, triangles (including skirts), subdivision level, measured maximum top edge, build time and estimated VBO/IBO bytes.

Budget pressure lowers the body-wide level; if even the source mesh exceeds the remaining budget, the body uses its original BSP draw and logs the fallback. Level is fixed for a map load, so there are no distance-dependent LOD seams. With `r_waterGeometry 0`, no extra mesh is uploaded and the regular modern-water/legacy paths continue.

## Distance-adaptive tessellation (`r_waterTessellation`)

`r_waterTessellation 1` (latched, default 0) draws the render mesh as triangle patches on a GL 4.3 context (`r_gl43 1`, `MODERN_TESSELLATION`: `glPatchParameteri` and `GL_MAX_TESS_GEN_LEVEL` ≥ 8). Without it, or with `r_waterGeometry 0`, the static mesh above is unchanged. Plan and rationale: `rend2-gl43-plan-5-water-tessellation.md`.

- **Base mesh.** `R_WaterBuildGeometry` subdivides `log2(r_waterTessMax)` fewer dyadic levels (level 6 at `r_waterTessMax 16` becomes level 2, 256 times fewer triangles). Skirts, shoreline data and the midpoint cache are as before. The IBO is flagged `waterPatches`; only those draws pick the `WATERDEF_USE_TESSELLATION` programs and `GL_PATCHES` (`RB_WaterSurfaceProgram`, `RB_IterateStagesWater`). The BSP mesh (`r_waterGeometryDebug 3`, budget fallbacks) stays triangles.
- **Programs.** The `_TESS` permutations (8 more, compiled only when available) give every stage `#version 430 core` (`ShaderProgramBuilder::SetModernVersion`). The `/*[Vertex]*/` block of `watersurface.glsl` is compiled twice: as the vertex stage it only decodes control points, as the evaluation stage (`WATER_TESS_EVALUATION`) its attributes are globals that the evaluation `main` interpolates before calling the same `WaterVertex` body as the untessellated program, so there is one copy of the vertex logic. A new `/*[TessControl]*/` block picks the levels. `GPUSHADER_TESS_CONTROL` / `GPUSHADER_TESS_EVALUATION`, the `TessControl` / `TessEvaluation` block names and the `_tc` / `_te` suffixes are generic.
- **Levels.** Edge level = `clamp(L · K / d, 1, r_waterTessMax)`, `L` the world edge length, `d` the distance from the camera to the edge midpoint, `K = P00 · viewportWidth / (2 · r_waterTessPixels)` (`u_WaterTess.x`; the reflection prepass multiplies it by its resolution scale). The level depends only on the two ends of the edge (computed symmetrically, `precise`), and the evaluation stage interpolates positions with `precise`, so patches sharing an edge produce bit-identical vertices: no cracks. Spacing is `fractional_odd_spacing`. Inner level = max of the edges. A skirt patch splits only its top edge (the edge between two `TexCoord1.x = 1` vertices, which matches the surface edge above it); its other edges and inner level are 1. Patches whose box, expanded by the body's maximum displacement (`tessCullExtent`: waves, interaction, wall pile margin), lies outside one plane of the view (far plane excepted) get level 0 and are dropped.
- **Geometry waves.** `R_WaterGeometryComponentCount` offers the one or two longest components that the finest level can resolve (wavelength ≥ 4 · base max edge / `r_waterTessMax`). The evaluation stage weighs each candidate by `smoothstep(4, 6, wavelength / localEdge)`, with `localEdge = clamp(d / K, baseEdge / maxLevel, baseEdge)` from the vertex position alone (crack free). The fragment stage gets the weights (`var_TessInfo`) and adds `(1 − w)` of each candidate to its shading remainder (`waterGeometryWeights` in `water_surface_common.glsl`), so geometry + shading always sum to the full spectrum. The weights always use the main-view `K`, so the reflection prepass sees the same waves on a coarser mesh. The CPU waterline estimate (`R_WaterlineWaveHeight`) still counts the full candidates, which matches near the camera where the weights are 1.
- **Shoreline.** Control points carry the decoded `(distance, rigid)`, not the signed encoding, which would flip sign midway across a rigid/natural edge. Attenuation is computed from the interpolated distance: in the evaluation stage for the displacement, and again per pixel in the fragment stage (`var_ShoreDataRaw`), because tessellated triangles can be wider than the shore falloff. The distance to one straight boundary is linear over a triangle, so a coarse base keeps the fine falloff.
- **Motion vectors.** The previous-frame position is evaluated at the same interpolated base point with the same weights. Levels depend only on the current camera, so vertices may slide across the surface between frames, but each vertex's previous position names the same surface point.

CVARs: `r_waterTessellation` (latched), `r_waterTessPixels 96` (live; 12 was denser than the static mesh near the camera and gave no gain, 96 renders the `t3_hevil` lake in 73 ms instead of 99–120 ms on Intel UHD at 1080p, 128+ saturates at 68 ms; plan 5 status has the table), `r_waterTessMax 16` (latched, 2 up to the driver limit), `r_waterTessMinEdge 0` (live: the shortest tessellated edge in world units, so near-camera detail can be capped, e.g. 64 = never finer than the static mesh; the geometry-wave weights use the same floor), `r_waterTessLodDistance 0` (live: within this distance edges are as fine as the two limits allow, beyond it the pixel rule counts the distance from there, so "full detail up to N units, then LOD" is one setting), `r_waterTessForce 0` (cheat: one level for every surface edge, for comparisons). `r_waterGeometryDebug 1` shows the tessellated wireframe; mode 6 is a level heat map (blue 1, green half, red max) darkened where the longest wave is left to shading. `r_waterGeometryInfo` adds the base triangle count and the triangles of the main water pass from a `GL_PRIMITIVES_GENERATED` query taken about once per second and read without waiting.

GPU test: `tools/rend2/test_water_tessellation_gl.py` (Intel UHD and RTX 2060 pass): every `_TESS` permutation links; no uncovered pixel on a grazing base grid spanning levels 1–16 with geometry waves, while a deliberately per-patch level leaves holes; `r_waterTessForce 4/8` matches the static mesh 4/8 times finer to < 5e-4 relative depth; weights 1 near and 0 far; out-of-view patches produce 0 primitives; a skirt patch splits only its top edge; shore distance and attenuation of an 800-unit base triangle match an 8-unit static mesh. `--bench` times a 6000 × 6000 lake.

## Verification

Use a grazing camera angle with `r_waterSurface 1; r_waterWaves 1; r_waterGeometry 1`, compare debug mode 3 to 0 and inspect mode 1. Keep the camera above the highest crest when comparing silhouettes; placing it inside a crest exercises underwater compositing instead. The principal stock cases are the huge `t3_hevil` lake, six `t2_rancor` pools, shallow `yavin1` patches, `vjun1` slime, and a joined multi-surface body such as `t3_hevil` body 9. `r_waterGeometryInfo` exposes fallbacks on each map.

The OpenGL 3.2 shader test verifies that displacement changes rasterized water depth. The SP runtime test loaded all four maps with the mesh and captured grazing, wireframe, magnitude, original-mesh and seam views. On `t3_hevil`, body 9 built 73,668 vertices and 144,640 triangles at level 6 (328 ms and 17.6 MB for the entire map); its wireframe and original-mesh comparison show the added geometry and moving surface. `t2_rancor` also passed with `r_waterGeometry 0`. SP and MP rend2 DLLs compiled with MSVC and MinGW. The stock audit establishes topology and body membership; unusual custom-map seams still need a visual check because unmatched source edge partitions use skirts rather than body-wide remeshing.

# План 2. Списки источников froxel fog на GPU

Относится к [rend2-gl43-review.md](rend2-gl43-review.md), пункт 3. Объём: средний (2–4 дня). Зависит от плана 1
(те же инструменты сверки и замеров). Использует ядро Forward+ (`glsl/fplus_cluster.glsl`).

## Что сейчас

Сам froxel fog уже работает на compute: инжекция, проход сред, интеграция. Но списки динамических источников для
инжекции до сих пор строит CPU каждый кадр в `R_VolumetricBuildLightLists` (`shared/rd-rend2/tr_volumetric.cpp`).
Функция вызывается из `RB_UpdateVolumetricConstants` в бэкенде, до загрузки UBO. Порядок работы:

1. Собирает кандидатов: динамические источники сцены в порядке важности, сабли (LTC-линии), восстановленные
   статические источники (`R_StaticLights`), лучи от световых порталов (`R_StaticLightPortals`). Сортирует их по
   оценке `luminance · r² / dist²` и пишет данные источника, `FROXEL_LIGHT_TEXELS = 5` текселей RGBA32F на
   источник.
2. Для каждого источника `R_VolumetricLightRange` считает прямоугольник тайлов и диапазон срезов. Тайл — это
   N×N froxel, где N = `r_volumetricFogLightTile` (4, 8 или 16).
3. Проход 1 считает источники в каждом кластере (тайл × срез) с лимитом `FROXEL_LIGHTS_PER_CLUSTER = 32`. Затем
   префиксная сумма, проход 2 заполняет списки.
4. Результат — один буфер R32UI: заголовок на кластер (`первый элемент | число << 24`), за ним индексы. Он
   переопределяется через `glBufferData` (orphaning) в кольце `MAX_FRAMES`.

Инжекция (`glsl/volumetric_inject.glsl`) читает заголовок через `FroxelLightCluster(cell, slice)` и перебирает
источники в `DynamicLights`.

## Зачем переносить

- **CPU.** При 1080p и `gridScale 8` сетка froxel около 240×135, с тайлом 8 это 30×17 тайлов. При 64 срезах
  получается около 32 тыс. кластеров. Источник радиусом в несколько сотен единиц вблизи камеры накрывает тысячи
  кластеров, и оба прохода выходят на 10⁵–10⁶ итераций за кадр. `r_vfogLightStats` уже печатает это время
  («CPU build»), его надо замерить в плане 1.
- **GPU (главный выигрыш).** CPU кладёт источник во все кластеры его прямоугольника, включая углы, куда сфера
  не достаёт. Инжекция — самый дорогой проход froxel fog, и она перебирает список каждого кластера для каждого из
  N×N froxel тайла. Каждый лишний источник в списке — это вычисление освещения (тень, cookie, фаза, самозатенение
  сред), которое даёт ноль. Тест сферы с кластером на GPU выкидывает такие источники. В Forward+ это сократило
  ссылки на 10–14 %; во froxel срезы длиннее, поэтому эффект, вероятно, больше. Это нужно замерить.

## Как сделать

### 1. Ядро: обобщить `fplus_cluster.glsl`

Не копировать файл, а добавить второй режим через define. `GLSL_LoadComputeProgram` принимает `defines`, поэтому
получатся две программы из одного источника: `tr.forwardPlusClusterShader` с `""` и
`tr.froxelLightClusterShader` с `"#define FROXEL_LIGHT_LISTS\n"`.

Отличия режима `FROXEL_LIGHT_LISTS`:

| | Forward+ | Froxel |
|---|---|---|
| срезы | срез 0 = [0, nearSlice], дальше логарифмические `exp((s−1−bias)/scale)` | `R_VolumetricSliceDistance(k) = near · (far/near)^(k/N)`, срез 0 = [0, d(1)] |
| тайл → NDC | `x · tile / viewportWidth` (пиксели) | `x · tile / s_vf.width` (froxel) |
| проекция | проекция вида (`p[8]`, `p[9]` — джиттер) | `froxelProjection`: копия проекции вида, у которой `p[2]` и `p[6]` обнулены, то есть джиттер TAA убран |
| формат выхода | grid RG32UI + индексы R16 | один R32UI: заголовок `first \| count << 24`, индексы 32 бит |
| лимит | `r_forwardPlusMaxLightsPerCluster` | `FROXEL_LIGHTS_PER_CLUSTER` (32) |
| расширение AABB | маленький запас на логарифм | **джиттер инжекции**, см. ниже |

**Джиттер — главное отличие.** Инжекция считает освещение не в центре froxel, а в точке
`center + u_FroxelJitter.xyz · temporal` (`volumetric_inject.glsl`, около строки 1526). Джиттер лежит в
[−0.5, 0.5] froxel по x/y и в срезах по z (Halton, 8 кадров, `RB_UpdateVolumetricConstants`). Значит, точка, для
которой берётся список кластера, может выйти за кластер на полфроксела. AABB кластера надо расширить на 0.5 froxel
по x/y с каждой стороны, а по глубине взять `d(k − 0.5) … d(k + 1.5)` (дробный показатель в той же формуле).
Иначе источник на границе пропадёт в части кадров, и в истории появится мерцание.

Шаг реализации: найти все вызовы `FroxelLightCluster` (сейчас около строк 1540 и 1645) и все точки, где списки
используются: центр froxel, джиттерированная точка, центр частиц `pc`, хвост за `far` (потоки z == 0 в compute,
тот же `var_Slice`). AABB должен покрывать каждую из этих точек. Для **последнего среза и хвоста** проще не
делать тест сферы вообще (как сейчас на CPU, только прямоугольник): хвост лежит за `far`, и считать его AABB
дорого и ненадёжно.

**Типы источников.** У каждого есть ровно одна ограничивающая сфера:
- точечный и spot — `R_SpotBoundingSphere`;
- сабля в режиме point proxy и линия — сфера `dl->radius`;
- луч портала — синтетический `dlight_t` с центром посередине луча и радиусом, покрывающим апертуру и разлёт;
- восстановленные статические источники — как точечные.

Поэтому тест сферы можно делать для всех, флаг `sphere` всегда 1, кроме последнего среза.

### 2. CPU-сторона (`tr_volumetric.cpp`)

- `froxelLightRange_t` расширить сферой в пространстве вида. `R_VolumetricLightRange` уже считает `eye` и
  `radius`: сохранить их в range.
- Кандидатов, данные источников, выбор самозатеняемых (`block->selfShadowLights`) и загрузку буфера источников
  оставить на CPU. Это O(число источников) и дёшево.
- Новая функция `RB_VolumetricBuildLightListsGPU(...)` вместо проходов 1–2. Включается при
  `R_HasModernFeatures(MODERN_COMPUTE | MODERN_SSBO)`, наличии `tr.froxelLightClusterShader.program` и новом
  cvar `r_volumetricFogLightCompute 1` (по умолчанию 1, переключается без рестарта, решение принимается на кадр).
  Функция:
  - загружает записи диапазонов (те же 32 байта, что у Forward+) в свой SSBO на слот кадра;
  - обнуляет счётчик (4 байта, `glBufferSubData`), ставит `qglMemoryBarrier(GL_SHADER_STORAGE_BARRIER_BIT)`;
  - один диспатч на `numClusters` потоков, затем `qglMemoryBarrier(GL_TEXTURE_FETCH_BARRIER_BIT)`. Инжекция
    читает буфер как buffer texture.
- **Буфер списков.** Сейчас он переопределяется по размеру каждый кадр. Для GPU нужна фиксированная ёмкость на
  слот: `numClusters` заголовков плюс область индексов. Худший случай `numClusters · 32` (около 1 млн элементов,
  4 МБ на слот) — допустимо. Выделять при создании froxel-ресурсов (`R_CreateVolumetricFBOs`), пересоздавать при
  смене сетки. Индекс `first` в заголовке — 24 бита: проверить, что `numClusters + ёмкость < 2²⁴`, иначе работать
  на CPU.
- Поле `block->lightTileSize / lightTilesX / lightTilesY` заполняется как сейчас.
- `r_vfogLightStats` в GPU-режиме печатает только время CPU-части. Статистика по кластерам доступна при
  `r_volumetricFogLightCompute 0`, как у Forward+.

### 3. Загрузка программы (`tr_glsl.cpp`)

В `GLSL_LoadGPUProgramForwardPlusCluster` загрузить вторую программу с define, если включён froxel fog
(`R_VolumetricFroxelEnabled()`). Удалять в `GLSL_ShutdownGPUShaders`. Добавить +1 в
`GLSL_CountStartupPrograms`.

### 4. Тест (`tools/rend2/test_gl43_compute.py`)

Новый `froxel_case` на основе `fplus_case`:
- Python-порт `R_VolumetricLightRange` и CPU-раскладки (проходы 1–2, формат `first | count << 24`).
- Проверки:
  - GPU-список — подпоследовательность CPU-списка;
  - лимит 32;
  - все источники, достающие до любой точки кластера **с учётом джиттера** (сетка точек от −0.5 до +0.5 froxel по
    x/y и по срезу), присутствуют;
  - последний срез совпадает с CPU в точности.
- Случаи: срезов 64 и 128, тайл 4/8/16, большой и малый радиус, источник у самой камеры (сфера пересекает
  плоскость камеры: на CPU в этом случае весь вид).

### 5. Проверка в игре

- `r_volumetricFog 2`, тестовые источники (`r_forwardPlusSpawnTestLights 64`, они попадают и во froxel),
  туман высоты.
- Скриншоты `r_volumetricFogLightCompute 0` и `1` при `r_volumetricFogTemporal 0` (без истории, детерминированно):
  разница должна быть ровно 0 вне переполненных кластеров, так как вне сферы вклад нулевой. С историей сравнить
  визуально на мерцание.
- Таймер «Froxel fog inject» (`r_speeds 100`) и время CPU из `r_vfogLightStats`: до и после.
- Команда-сверка `r_vfogLightVerify` по образцу `r_forwardPlusVerify` из плана 1.

## Риски

- Пропуск источника из-за неверного AABB (джиттер, хвост) даст мерцание света в тумане. Лечится расширением AABB
  и тестом с джиттером.
- `froxelProjection` отличается от проекции вида: использовать именно её, иначе тайлы не совпадут с инжекцией.

## Готово, когда

- тест проходит на Intel и NVIDIA;
- скриншоты без истории совпадают бит в бит;
- замерено время CPU и GPU-время инжекции;
- документация обновлена в [rend2-volumetric-fog.md](rend2-volumetric-fog.md) и в обзоре.
